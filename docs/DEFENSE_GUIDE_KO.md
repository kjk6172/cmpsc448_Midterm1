# 프로젝트 이해·발표 가이드

이 문서는 제출 보고서의 내용을 직접 설명할 수 있도록 돕는 한국어 학습 자료입니다. 실제 수치는 `artifacts/main_aggregate.csv`, `artifacts/results.csv`와 `report/project_report.pdf`에서 확인하세요. 보고서 작성에 AI를 사용했으며, 실제 실행 기록과 저장된 결과를 근거로 작성했습니다. 팀원이 수행하지 않은 일을 수행했다고 주장하지 마세요.

## 1. 한 문장으로 설명하기

동일한 공개 질문에 대해 서로 다른 세 LLM이 작성한 답변을 모으고, CNN과 LSTM으로 작성 모델을 분류했다. 질문만, 답변만, 질문과 답변을 함께 사용하는 세 조건을 비교했으며, 학습에 없는 출처의 질문으로 일반화와 답변의 형식·어휘 특징을 추가 조사했다.

## 2. 왜 같은 질문을 사용하는가?

모델 A에게 코딩 문제만, 모델 B에게 작문 문제만 주면 분류기는 모델의 문체 대신 질문의 주제를 외울 수 있습니다. 같은 질문마다 세 모델의 답변이 하나씩 있는 데이터를 쓰면 질문 분포가 완전히 같아집니다. 같은 질문과 비슷한 질문 template를 묶은 `split_group_id` 단위로 train/validation/test를 나누므로 동일 질문·탐지된 유사 질문은 여러 분할에 등장하지 않습니다. 448개 질문이 429개 그룹으로 묶입니다.

이 설계의 중요한 검증은 질문만 사용하는 실험입니다. 같은 질문 텍스트가 세 정답 라벨과 한 번씩 묶이면, 결정적으로 동작하는 분류기는 질문만으로 세 개 중 하나만 맞힐 수 있으므로 정확도는 정확히 1/3입니다. 높은 성능이 나오면 좋은 결과로 받아들이기 전에 라벨 누수·불균형·모델별 전처리 차이를 확인해야 합니다. Macro-F1은 모든 항목을 같은 클래스로 예측하면 정확도보다 낮을 수 있습니다.

## 3. CNN과 LSTM의 차이

- **CNN:** 임베딩으로 바꾼 토큰에서 짧은 구간을 convolution 필터로 읽고, 중요한 패턴을 pooling으로 모아 분류합니다. 짧은 문구나 형식 패턴을 감지하는 데 적합한 설계입니다.
- **LSTM:** RNN의 일종으로, 이전 토큰에서 얻은 정보를 상태에 보관하며 순서대로 읽습니다. 이 프로젝트의 정확한 방향 수·hidden 크기·pooling 방법은 보고서의 모델 표와 `src`의 실제 구현에서 확인합니다.
- 어느 쪽이 항상 우수하다고 단정하지 않습니다. 이 데이터와 설정에서 실제 측정한 결과만 비교합니다.

## 4. 연구 질문별 답변 준비

| 질문 | 실험 | 설명할 때 확인할 점 |
|---|---|---|
| RQ1: 답변으로 작성 LLM을 맞힐 수 있는가? | Output-only CNN/LSTM | Accuracy, Macro-F1, confusion matrix, 1/3 chance baseline |
| RQ2: 질문이 도움이 되는가? | Input-only / Output-only / Input+Output | 같은 모델 내 성능 차이, 동일한 분할과 seed, 질문만 조건의 의미 |
| RQ3: 새로운 질문 출처·작문 분야로 일반화하는가? | Self-Instruct 출처 holdout와 writing 주제 holdout | 실제 출처 구분과 키워드로 만든 주제 구분의 차이, 학습 데이터 수 차이 |
| RQ4: 어떤 특징이 구별에 관련되는가? | 길이·어휘·형식 통계 및 제거 실험 | 상관관계와 원인의 차이, 제거 실험에서 무엇까지 결론낼 수 있는지 |

## 5. 평가 지표를 설명하기

**Accuracy**는 전체 정답 비율입니다. **Macro-F1**은 클래스별 precision과 recall에서 구한 F1을 클래스마다 같은 가중치로 평균한 값입니다. 특정 모델만 잘 맞히는 상황을 확인하는 데 유용합니다. **혼동행렬**의 행은 실제 모델, 열은 예측 모델입니다.

Seed는 초기 가중치와 minibatch 순서 등의 무작위성을 제어합니다. 여러 seed의 평균과 표준편차는 학습의 변동성을 보여주지만, 작은 표준편차가 데이터 편향을 없애주지는 않습니다. 같은 테스트 질문을 반복 평가한 seed 결과는 독립적인 새 테스트 데이터가 아닙니다. 질문마다 세 답변이 연관되고 비슷한 template도 연관되므로 bootstrap에서는 답변 행 대신 `split_group_id`를 다시 뽑습니다. 두 조건의 차이는 동일 그룹으로 paired bootstrap을 합니다.

RQ2에서 답변만 조건과 질문+답변 조건은 모두 답변을 최대 256토큰까지 봅니다. 질문+답변은 질문 최대 64토큰과 구분자 하나를 앞에 더해 최대 321토큰입니다. 질문 때문에 답변의 관찰 길이가 줄어드는 문제를 피하도록 설계했습니다.

## 6. 자주 나오는 질문

**왜 더 큰 pretrained Transformer를 쓰지 않았나요?**

과제에서 요구한 CNN과 RNN을 직접 구현해 비교하는 것이 기본 목표입니다. 작은 모델은 구조·학습·오류를 설명하기 쉽습니다. 추가 baseline이 있다면 그것은 비교 기준이며 필수 모델을 대체하지 않습니다.

**답변에 모델 이름이 있으면 바로 맞힐 수 있지 않나요?**

그렇기 때문에 curation에서 명시적 자기소개나 모델 이름 단서의 처리 방법을 기록하고, 클래스 라벨·generator 열을 입력 텍스트에 넣지 않습니다. 처리해도 다른 단서가 남을 수 있으며 이는 한계로 설명합니다.

**RQ3에서 출처가 다르면 분야가 다른 건가요?**

완전히 같지 않습니다. 데이터셋의 source 구분은 객관적인 출처 변화입니다. 그것만으로 모든 코딩·수학·작문 분야 일반화를 입증했다고 주장할 수 없습니다. 보고서에서 실제 사용한 구분과 범위를 설명해야 합니다.

**Formatting 제거 후 성능이 낮아지면 CNN이 Markdown을 쓴다고 증명되나요?**

관련 신호가 있었다는 증거는 되지만, 원인을 하나로 확정하지는 못합니다. 제거 전후 토큰 수·문장 경계·정보량도 변할 수 있습니다. 제거 모델을 다시 학습했는지, 학습된 모델에 변환된 테스트 텍스트만 넣었는지도 구별해야 합니다.

**높은 정확도면 실제 온라인 글에도 바로 쓸 수 있나요?**

세 모델·공개 benchmark·특정 버전에 한정된 closed-set 분류입니다. 최신 버전, 인간 글, 편집된 답변, 섞인 글, 미등록 모델은 검증하지 않았습니다. 실제 시스템에서 정답이라고 확신하는 사용은 이 프로젝트의 결과 범위를 넘습니다.

**AI가 작성했는데 팀이 무엇을 해야 하나요?**

AI 도움은 과제에서 허용하지만, 학생은 제출물 전체를 이해·검증·설명할 책임이 있습니다. 두 팀원 모두 보고서를 읽고 주요 실험과 코드를 설명할 수 있어야 합니다. 개인 역할은 실제 기여 내용에 맞게만 기록하세요.

## 7. 발표 5분 구성

1. 30초: 문제·세 모델·질문 공정성.
2. 60초: 공개 데이터의 출처·동일 질문 매칭·그룹 단위 분할.
3. 60초: CNN/LSTM 구조와 공통 학습 조건.
4. 90초: 실제 main table·혼동행렬·RQ2 차이.
5. 60초: RQ3/RQ4 결과, 가장 중요한 한계, 학습한 실험 설계 원칙.

발표에서 사용할 숫자는 최종 PDF에 저장된 수치만 사용하세요. 좋은 결과만 고르지 말고 나빠진 조건도 설명하는 것이 분석의 핵심입니다.

## 8. 이번 수정에서 배운 점

- Koala의 학습 사용 금지 요청을 확인한 뒤 최종 데이터의 모든 분할에서 제외하고 38개 실험을 재실행했습니다. 출처 고지만으로 이용 범위 문제를 해결했다고 주장하지 않습니다.
